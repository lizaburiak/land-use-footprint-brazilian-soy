# SOYPRINT results database

A queryable database of the pipeline's per-municipality results, in three layers:

1. **Parquet** (canonical, publication-ready): `data/db/parquet/<table>/year=YYYY/data.parquet`
   — hive-partitioned, language-agnostic (R/arrow, Python/pandas, QGIS, DuckDB).
2. **DuckDB** (working copy): `data/db/soyprint.duckdb` — a single self-contained
   file with all tables materialised plus analysis views. Open it from R
   (`duckdb` package), Python (`import duckdb`), or any SQL client (DBeaver, harlequin).
3. **CSV** (easiest, optional): `data/db/csv/` — every table dumped to plain CSV,
   plus small ready-made summary tables. See "CSV layer" below.

## Build

```sh
Rscript code/db/export_parquet.R --all          # stage 1: results rds -> parquet (~30 min)
Rscript code/db/export_inputs_parquet.R --all   # stage 1b: inputs rds -> parquet (fast)
.venv/bin/python code/db/build_duckdb.py        # stage 2: parquet -> duckdb + QA
.venv/bin/python code/db/export_csv.py          # stage 3 (optional): duckdb -> csv
```

Stage 1 skips already-exported partitions unless `--force` is given; a single year
can be (re)exported with `Rscript code/db/export_parquet.R 2019 --force`.
Stage 2 always rebuilds the whole `.duckdb` (fast) and prints a QA report.
Stage 3 regenerates `data/db/csv/` from the .duckdb (~1.1 GB; `--skip-big` for
just the small tables + summaries).

An entity-relationship diagram of the database (crow's-foot notation, rendered
with Graphviz from the live schema) is generated by
`.venv/bin/python code/db/make_erd.py` into
`paper/main/figures/fig_db_schema.pdf` (+ editable `.dot` source alongside).
`--simple` writes a compact variant (`fig_db_schema_simple.pdf`): column names
only with primary keys in bold, one connector per table pair, no metadata
tables. `--inputs` writes the ERD of the input tables
(`fig_db_inputs_schema.pdf`).

## Fact tables

All facts carry a `year` column (from the hive partition). Units: tonnes, hectares, USD.

| table | grain | columns | source |
|---|---|---|---|
| `production` | mun | area_planted_ha, area_harvested_ha, production_bean_t, processed_bean_t, production_oil_t, production_cake_t | step 05 `SOY_MUN_fin` |
| `domestic_use` | mun × product × use_category | tonnes; categories: food, feed, seed, processing, other, stock_change | step 05 `SOY_MUN_fin` (melted) |
| `trade` | mun × product × flow × partner | partner_iso3, hs4, tonnes, value_usd; flow = export/import | step 05 `EXP/IMP_MUN_SOY_cbs` (Comex, CBS-balanced) |
| `export_attribution` | mun × product × destination × method | tonnes; method = euclid / multimode_mean | step 08 `source_to_export_mean` — exports *attributed to producing* municipality via the transport model (vs `trade`, which records the *exporting* municipality) |
| `transport_flows` | mun_orig × mun_dest × product × method | tonnes | step 08 `flows_mu` |
| `footprint_country` | mun × consumer country × demand | hectares; demand = food (FABIO) / nonfood (EXIOBASE) | step 20 `F_mass` A/B_country, soy rows (`co_mun`, c021) |
| `footprint_product` | mun × consumer product | hectares; product_family = fabio (comm_code) / exiobase (sector name) | step 20 `F_mass` A/B_product |
| `footprint_animal_country` | mun × consumer country × animal item | hectares; the 8 individual FABIO animal commodities (c110–c118 excl. c113) | step 20 `F_mass` A_prod_country |

Notes on the footprint tables:

- `footprint_country` and `footprint_product` are complete marginals — each sums
  to the total footprint per year (QA-checked).
- `footprint_animal_country` is the only joint country × product cut the pipeline
  produces and it covers *only* animal end-uses (~half of total ha); it is not a
  complete decomposition. The group aggregates saved by step 20 (dairy, meat, …)
  are dropped here because they overlap; rebuild them by summing items.
- Nonfood consumer codes include the 5 EXIOBASE rest-of-world regions
  (WA/WE/WF/WL/WM), present in `dim_country` with `region = 'Rest of World'`.

## Input tables

Cleaned pipeline inputs (the harmonised raw data as steps 00-03 consume it,
before any balancing), exported by `export_inputs_parquet.R`. All carry a
`year` column; coverage 2000-2023 (feed: -2022).

| table | grain | columns | source |
|---|---|---|---|
| `input_municipality` | mun | the "grand input": area_plant/harv, prod_bean, exp/imp per product (t + USD), proc/ref facilities + capacity, population, livestock heads, storage_cap, oil_acq_pc, diesel_cap_soy | step 00 `SOY_MUN_00` |
| `input_trade` | mun × product × flow × partner | partner_iso3, partner_comex, hs4, tonnes, value_usd — raw COMEX, pre-CBS-balancing (vs `trade`, which is balanced) | step 00 `EXP/IMP_MUN_SOY_00` |
| `input_cbs_national` | product | FAO commodity balance for Brazil: production, trade, food/feed/seed/other/processing, stocks | step 00 `CBS_SOY` |
| `input_livestock_systems` | mun × animal | heads per production system (26 categories: cattle_gra_dair, pig_ind, chicken_bro, ...) | step 02 `LIVESTOCK_MUN_02` |
| `input_feed` | mun × animal | feed_bean_t, feed_cake_t per animal category | step 03 `bean/cake_feed_t` |
| `input_faostat_trade` | year × product × flow × partner | FAOSTAT bilateral benchmark (tonnes, 1000 USD) | raw/04 tradematrix |

## Dimensions

| table | keys | notes |
|---|---|---|
| `dim_municipality` | co_mun (7-digit IBGE) | name, state, biome (IBGE 1:250k, point-on-surface join), matopiba flag, lon/lat |
| `dim_country` | iso3c | name, continent, region, eu27 (FABIO `regions_full.csv` + EXIOBASE RoW) |
| `dim_commodity` | comm_code (FABIO c001–c130) | item, comm_group, enduse_bucket (same buckets as `prep_enduse_ha.R`) |
| `dim_soy_product` | product (bean/oil/cake) | HS4 and FABIO item codes |

## Views

- `v_footprint_by_country` — footprint joined to country names/regions.
- `v_footprint_by_enduse` — footprint by end-use bucket (Animal products / Soy
  commodity / Other food / Non-food industrial), reproducing `by_enduse_ha.csv`.
- `v_footprint_by_biome` — footprint origin aggregated to biome × demand.
- `v_soy_balance` — per municipality-year: area, production, processing, exports,
  domestic use side by side.

## Meta

- `meta_provenance` — source rds file + mtime per table-year export.
- `meta_build` — build timestamp, git commit/branch, duckdb version.

## CSV layer

For anyone who just wants files to open — no SQL, no packages:

```
data/db/csv/
  summaries/                       <- START HERE: small, Excel-friendly
    footprint_by_country_year.csv     year x country x food/nonfood, ha
    footprint_by_enduse_year.csv      year x end-use bucket, ha
    footprint_by_biome_year.csv       year x biome (+ matopiba), ha
    footprint_by_state_year.csv       year x state, ha
    national_soy_balance_year.csv     national area/production/exports per year
    top_municipalities_footprint.csv  top-100 footprint municipalities per year
  production.csv, trade.csv, domestic_use.csv, transport_flows.csv,
  export_attribution.csv           <- full fact tables, all years in one file
  dim_*.csv                        <- lookup tables (municipality names, countries...)
  footprint_country/               <- the 3 big mun-level tables, one .csv.gz per
  footprint_product/                  year (millions of rows — too big for Excel;
  footprint_animal_country/           R and pandas read .csv.gz directly)
```

`export_attribution.csv` (~100 MB) and `transport_flows.csv` (~43 MB) exceed
Excel's 1,048,576-row limit — fine in R/pandas/QGIS. Reading the compressed
per-year files needs no extra step:

```r
x <- data.table::fread("data/db/csv/footprint_country/footprint_country_2019.csv.gz")
```

```python
x = pandas.read_csv("data/db/csv/footprint_country/footprint_country_2019.csv.gz")
```

## Accessing the database

Everything is read-only for queries — safe to run while the pipeline writes elsewhere.

### Quickest: the query helper (Python venv, already set up)

```sh
.venv/bin/python code/db/query.py --tables            # list tables + views
.venv/bin/python code/db/query.py "SELECT * FROM production LIMIT 5"
.venv/bin/python code/db/query.py -f code/db/some_query.sql
.venv/bin/python code/db/query.py "SELECT ..." --csv > out.csv   # save result
.venv/bin/python code/db/query.py                     # interactive shell
```

### Python (for analysis scripts / notebooks)

`duckdb` is installed in `.venv`. Results come back as pandas DataFrames:

```python
import duckdb
con = duckdb.connect("data/db/soyprint.duckdb", read_only=True)
df = con.sql("SELECT year, sum(hectares) ha FROM footprint_country GROUP BY year").df()
```

### R

R here has `DBI` + `nanoparquet` but **not** the `duckdb` package. Two options:

- **No install** — read the Parquet partitions directly with `nanoparquet`:
  ```r
  library(nanoparquet)
  prod19 <- read_parquet("data/db/parquet/production/year=2019/data.parquet")
  # all years of a table:
  files <- list.files("data/db/parquet/production", "data.parquet$",
                      recursive = TRUE, full.names = TRUE)
  prod <- data.table::rbindlist(lapply(files, read_parquet), idcol = NULL)
  ```
  (This gives you the tables but not the SQL views — those live only in the .duckdb.)

- **Full SQL from R** — install the package once, then it works like any DBI backend:
  ```r
  install.packages("duckdb")            # one-time
  con <- DBI::dbConnect(duckdb::duckdb(), "data/db/soyprint.duckdb", read_only = TRUE)
  DBI::dbGetQuery(con, "SELECT * FROM v_soy_balance WHERE year = 2019 LIMIT 10")
  DBI::dbDisconnect(con, shutdown = TRUE)
  ```

### GUI / SQL client

Point any DuckDB-compatible client at `data/db/soyprint.duckdb`:
- **DBeaver** (free, cross-platform): New Connection → DuckDB → pick the file.
- **DuckDB CLI**: `brew install duckdb`, then `duckdb data/db/soyprint.duckdb`.
- **harlequin** (`pipx install harlequin`): `harlequin data/db/soyprint.duckdb`.

Only one process can hold a write lock, but many can open the file `read_only=True`
at once — always connect read-only unless you're the builder.

### Without the .duckdb file at all

The Parquet layer is queryable on its own (e.g. on a machine that only has the
Parquet, or after a Zenodo download):

```python
duckdb.sql("SELECT year, sum(hectares) FROM "
           "'data/db/parquet/footprint_country/year=*/data.parquet' GROUP BY year")
```

## Example queries

```sql
-- China's land footprint by biome, 2013 vs 2019
SELECT year, m.biome, round(sum(hectares)/1e6, 2) AS mha
FROM footprint_country f JOIN dim_municipality m USING (co_mun)
WHERE consumer_code = 'CHN' AND year IN (2013, 2019)
GROUP BY ALL ORDER BY year, mha DESC;

-- top exporting municipalities (attributed origin, multimode) 2019
SELECT m.nm_mun, m.nm_state, round(sum(tonnes)) AS t
FROM export_attribution e JOIN dim_municipality m USING (co_mun)
WHERE year = 2019 AND method = 'multimode_mean'
GROUP BY ALL ORDER BY t DESC LIMIT 15;
```

From R / Python:

```r
con <- DBI::dbConnect(duckdb::duckdb(), "data/db/soyprint.duckdb", read_only = TRUE)
DBI::dbGetQuery(con, "SELECT ...")
```

```python
import duckdb
con = duckdb.connect("data/db/soyprint.duckdb", read_only=True)

```

